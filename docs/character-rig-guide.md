# 캐릭터 그리기 가이드 — 뼈대와 자세를 먼저

> 이 저장소에서 사람이나 생물 캐릭터 문서를 만들 때의 순서. **파트를 놓기 전에
> 관절과 자세를 먼저 좌표로 적는다.** 파트는 관절에서 파생되고, 애니메이션은
> 관절을 돌린다. 아린(`ss.char.arin`, `scripts/walker.py`)이 이 순서의 예이고,
> 아래 §8의 실패 넷이 이 문서가 있는 이유다. 게임 쪽 계획은 feelers 저장소의
> `docs/character-redesign-plan.md`.

## 0. 순서

| 단계 | 정하는 것 | 산출물 |
| --- | --- | --- |
| 1 시점 | 카메라와 몸이 보는 방향 | "3/4 위, 화면 오른쪽-앞을 본다" 한 줄 |
| 2 크기 | 캔버스, 몸 높이, 머리 비율 | 32×32 · 26~28px · 머리 = 키의 1/3 |
| 3 뼈대 | 관절 좌표 — 어깨 라인, 엉덩이 라인, 머리, 발, 짐이 걸리는 점 | `SKELETON` 표 (§2) |
| 4 자세 | 기울기, 무게, 팔이 매달리는 각도, 시선 | `POSE` 표 (§3) |
| 5 덩어리 | 큰 것부터 — 머리, 몸통, 팔·다리, 짐 — 각각 **어느 관절에** 매달리는지 | 덩어리 → 관절 표 (§4) |
| 6 깊이 | 시점에서 무엇이 무엇 앞에 오는가 = 그리는 순서 | `parts` 배열 순서 (§4) |
| 7 파트 | 덩어리를 도형으로. 위치는 관절 + 길이 + 각도로 계산 | 문서의 `parts` |
| 8 동작 | 관절을 돌린다 (힌지 규칙) | `idle`, `walk` |
| 9 검사 | 경계, 실루엣, 대비, 그리고 §7의 질문 여섯 | `sheet.ts` · `inspect.ts` · `readability.ts` |

3 없이 7로 가면 파트가 "그럴듯한 자리"에 놓이고, 그 자리는 시점이 바뀌는 순간
틀린다. 아린의 팔이 세 번 그랬다.

## 1. 시점

이 게임은 반쯤 내려다본 3/4 시점이고, 몸은 **화면 오른쪽-앞 대각선**을 본다.
+x가 앞, +y가 아래, 원점은 캔버스 가운데. 왼쪽으로 걸을 때는 엔진이 프레임
전체를 거울상으로 뒤집으므로(`setFlipX`) 문서는 한 방향만 그린다.

이 시점에서 보이는 것과 안 보이는 것:

- 헬멧의 앞·오른쪽 2/3, 바이저는 머리 폭의 60%쯤
- 몸통의 앞면 전부. 어깨 라인이 살짝 기운다 — **가까운(오른쪽) 어깨가 낮고
  화면 왼쪽**, 먼(왼쪽) 어깨가 높고 화면 오른쪽
- 가까운 팔(오른팔) 전부, 몸통 **왼쪽** 옆구리에서 코트 앞에, 윤곽선에 반 걸쳐서
- 먼 팔(왼팔)은 몸통 **뒤**, 오른쪽(앞) 가장자리 밖으로 소매와 손이 1px 안팎
- 등의 짐은 위·왼쪽으로 살짝, 짐에서 오르는 더듬이는 머리 뒤·왼쪽으로
- 발 둘, 가까운 발이 왼쪽·아래

## 2. 뼈대 — 관절부터 좌표로

아린의 값. 새 캐릭터는 이 표를 복사해 숫자만 바꾼다. 파트에 좌표를 직접 찍지
말고 여기서 파생시킨다(`hang`, `below`). 관절은 이름과 함께 문서의 `skeleton`
블록으로 나가므로(§2.1) 고칠 것은 **관절 이름으로** 말한다 — "`shoulder_near`를
1px 아래로", "`hand_far`가 코트 밖으로 더".

먼저 좌우. 몸이 화면 오른쪽-앞을 보면 **정면을 보는 사람의 오른손이 보는 이의
왼쪽에 있는 것**과 같은 이유로, 오른쪽 어깨(가까운 쪽)가 화면 **왼쪽 아래**,
왼쪽 어깨(먼 쪽)가 화면 **오른쪽 위**에 온다. 이걸 반대로 잡은 것이 §8의
네 번째 실패다.

| 관절 | 아린 | 뜻 |
| --- | --- | --- |
| `shoulder_near` | (−4.8, −3.0) | 가까운(오른) 어깨. 아래·**왼쪽** |
| `shoulder_far` | (5.6, −4.4) | 먼(왼) 어깨. 위·**오른쪽**. 둘을 이은 **어깨 라인**의 기울기 ≈ 7° |
| `neck` / `pelvis` | 어깨 라인 중점 / 엉덩이 라인 중점 | 척추의 양끝. 파생 |
| `hip_near` / `hip_far` | (−2, 12) / (3.4, 11.2) | 엉덩이 라인. 어깨보다 덜 기운다 |
| `head` | (2, −8), 기울기 −10° | 머리 중심. 어깨 라인 위, 앞으로. 머리가 어깨를 덮는다 |
| `hand_near` / `hand_far` | 소매 끝, 파생 | 어깨에서 소매 길이 + 0.9 |
| `foot_near` / `foot_far` | (−1.6, 13.1) / (3.6, 12.5) | 접지점. 가까운 발이 왼쪽·아래 |
| `pack` | (−6, −3.6) | 짐이 걸리는 점 — 등, 위·왼쪽 |
| `feeler_root` / `feeler_far_root` | (−5.4, −5.9) / (−6.8, −5.5) | 더듬이 뿌리 — 짐의 뚜껑 |

### 2.1 문서의 `skeleton` 블록과 보는 법

생성기는 관절과 뼈를 문서에 함께 쓴다:

```jsonc
"skeleton": {
  "joints": { "shoulder_near": [-4.8, -3.0], "shoulder_far": [5.6, -4.4], "head": [2, -8], … },
  "bones": [["shoulder_near", "shoulder_far"], ["neck", "pelvis"], ["shoulder_near", "hand_near"], …]
}
```

베이크에는 들어가지 않는다 — 파트를 놓은 발판일 뿐이다. 보는 길은 둘:

- **갤러리**: 캐릭터를 열면 `silhouette` 옆에 `skeleton` 토글이 있다. 켜면 관절이
  점으로, 뼈가 선으로, 이름이 곁에 그려진다. 정지 자세이고, 파트가 움직여도
  뼈대는 그 자리다 — 그래서 걷기를 켜 두고 보면 파트가 관절에서 얼마나 벗어나는지
  보인다.
- **inspect**: `npx tsx scripts/inspect.ts ss.char.arin --skeleton`.

`check`는 뼈가 없는 관절을 가리키면 오류로 잡는다.

규칙:

- **팔은 어깨 라인의 끝에 매달린다.** 몸통 안쪽 어디가 아니다. 가까운 소매는
  윤곽선 안으로 반, 밖으로 반. 먼 소매는 몸통 뒤에서 밖으로 1px 안팎.
- **어깨 라인은 기운다**, 4~8°. 수평이면 정면이고, 정면은 이 게임의 시점이
  아니다.
- **머리는 어깨 라인 위에 얹히고 앞으로 나온다.** 머리 중심의 x는 어깨 라인
  중점보다 1~3 앞. 헬멧 아래쪽이 어깨를 가린다.
- 발은 엉덩이 라인 바로 아래. 옷자락이 발의 위쪽을 덮는다.

## 3. 자세

| 항목 | 아린 | 규칙 |
| --- | --- | --- |
| line of action | 코트 +2° 앞으로 | 서 있는 몸도 완전한 수직은 아니다. 2~4° |
| 팔이 매달리는 각 | 가까운 팔 +6°, 먼 팔 −8° — 둘 다 몸 **밖**으로 | 0°면 막대기다. 앞뒤가 아니라 **안팎**으로 벌어진다 |
| 무게 | 가까운 발이 0.4 앞 | 접지점 둘 사이에 무게중심 |
| 시선 | 바이저 (머리 + (1.6, 1.2)), −5° | 머리 중심에서 앞·아래. 정면을 보는 바이저는 시점과 싸운다 |

## 4. 덩어리와 깊이

큰 것부터, 그리고 각각이 어느 관절에 걸리는지. `parts` 배열은 **먼 것부터
가까운 것**이다 — 이 시점에서의 깊이가 곧 그리는 순서다.

| 순서 | 덩어리 | 걸리는 관절 | 앞/뒤 |
| --- | --- | --- | --- |
| 1–2 | 더듬이 둘 | `feeler_*_root` | 가장 뒤. 머리 뒤·왼쪽으로 솟는다 |
| 3–4 | 짐 (발생기 상자, 랙) | `pack` | 먼 어깨 뒤 |
| 5–6 | 먼 팔 (소매, 손) | `shoulder_far` | 몸통 뒤, 오른쪽 |
| 7–8 | 발 둘 | `foot_*` | 옷자락 아래 |
| 9 | **코트 — 몸의 덩어리 하나** | 어깨 라인 → 엉덩이 아래 | |
| 10–11 | 망토, 걸쇠(기관) | 어깨 라인이 망토의 윗변 | 코트 위 |
| 12–13 | 가까운 팔 (소매, 손) | `shoulder_near` | 코트 위, 왼쪽 옆구리 |
| 14–15 | 헬멧, 바이저 | `head` | 가장 앞. 어깨를 덮는다 |

## 5. 파트로 옮길 때

- 위치는 **관절 + 길이 + 각도**. `hang(joint, len, angle)`이 링크의 중심을,
  `below(joint, dist, angle)`이 그 선 위의 점을 준다. 손은 소매와 같은 선 위,
  소매 길이 + 0.9.
- 팔은 소매 하나에 손 하나, 어깨 한 곳에서만 꺾인다. 링크 둘짜리 팔은 43px에서
  막대기로 읽힌다.
- 파트 수는 로스터와 같은 밀도: 같은 크기의 적이 11~19. 얼굴 없음, 그라데이션
  없음, 값은 셋(가장 밝은 머리 · 몸 · 어두운 발·손·바이저·기관).
- 파트 이름은 부위 이름(`arm_far`, `hand`), 도형 이름이 아니다.

## 6. 동작 — 관절을 돌린다

문서의 `rot`은 파트 **자기 원점** 기준이다. 관절 둘레로 돌리려면 회전에 더해
관절에서 중심까지의 벡터가 쓸고 간 x/y를 함께 넣어야 한다 — `swing(joint,
centre, θ)`가 그 셋을 준다. 뼈대가 먼저 있으면 트랙은 관절 각도의 함수 하나로
끝난다: 팔 트랙 여섯 개가 `arm_tracks(shoulder, [소매, 손], 부호)` 한 줄이다.

걷기는 접지-통과-접지-통과 네 자세다. 머리가 움직임을 나른다(32px에서 1~2px).
발은 땅에 있는 동안 뒤로 밀고 들 때만 앞으로 온다(문워크 검사). 팔은 같은 쪽
발과 **반대** 위상, 어깨 둘레로 ±14°. 더듬이는 뿌리보다 반 박자 늦는다.

## 7. 검사 — 자세에 대한 질문 여섯

`npx tsx scripts/sheet.ts <id> --anim walk`(경계, 프레임),
`npx tsx scripts/filmstrip.ts <id> walk --frames 8 --scale 8`(팔과 발의 위상),
`npx tsx scripts/inspect.ts <id> --anim`(실루엣, 게임 배율),
`npx tsx scripts/readability.ts <id>`(바닥 대비)를 돌린 다음, 큰 렌더를 보며:

1. 어깨 라인이 보이는가, 기울어 있는가? (`skeleton` 토글을 켜고 본다)
2. 팔이 어깨 라인의 **끝**에서 시작하는가? (가슴에서 시작하면 틀렸다)
3. 가까운 팔이 **화면 왼쪽**에 있고 소매가 윤곽선에 반 걸치는가? 오른쪽에
   있으면 몸이 왼쪽-앞을 보는 그림이다
4. 먼 팔이 몸통 뒤에 있고 오른쪽에 살짝만 보이는가?
5. 머리가 어깨를 덮는가, 앞으로 나와 있는가?
6. 검은 실루엣만으로 로스터의 다른 몸과 구분되는가?

하나라도 아니면 파트가 아니라 §2·§3의 숫자를 고친다.

## 8. 실패 기록 — 이 순서가 있는 이유

아린의 팔은 네 번 그려졌다.

| | 무엇을 했나 | 왜 틀렸나 |
| --- | --- | --- |
| 1 | 관절 링크 둘짜리 팔다리를 세운 우주인 | 뼈대는 있었지만 시점이 없었다. 정면도 옆도 아닌 막대기 |
| 2 | 팔을 없애고 손만 옷자락 가장자리에 | 관절이 없으니 손이 어디에도 걸리지 않고 떠 있었다 |
| 3 | 팔을 어깨에 매달되 가슴 앞에 | 어깨 라인을 긋지 않아 "어깨"가 몸통 안쪽 아무 데였다 |
| 4 | 어깨 라인을 긋되 가까운 어깨를 화면 **오른쪽**에 | 좌우를 뒤집었다. 오른쪽-앞을 보는 몸의 오른쪽 어깨는 보는 이의 왼쪽이다 |
| 5 | 가까운(오른) 어깨를 왼쪽 아래, 먼(왼) 어깨를 오른쪽 위에 | 됐다. 위 §2의 숫자가 그것이다 |

다섯 다 같은 잘못이다: 파트를 먼저 놓고 뼈대를 나중에 짐작했거나, 뼈대를
그리되 시점을 3D로 생각하지 않았다.

## 9. 코트 없는 몸 — 미나 (`ss.char.mir`)

미나는 여덟 중 유일하게 슈트를 입지 않는다. 몸의 윤곽이 곧 주 도형(모래시계)이고,
그 위에 식물이 붙는다. 참고는 League of Legends의 자이라 — 창백한 초록 피부, 뒤로
흐르는 붉은 덩쿨 머리, 잎으로 된 옷, 다리에 감긴 덩쿨. 문서 id는 게임이 고정해 둔
`ss.char.mir` 그대로이고, 플레이어가 읽는 이름은 행의 `display`("Mina")로 나간다.

생성기에 더한 것 — 나머지 일곱의 문서는 한 바이트도 바뀌지 않는다:

| 이름 | 종류 | 하는 일 |
| --- | --- | --- |
| `coat: "hourglass"` | 몸 | 코트가 아니라 몸: 앞 가장자리의 가슴, 조인 허리, 뒤로 나온 엉덩이. 엉덩이에서 끝나고 아래는 `legs` |
| `head: "face"` | 머리 | 헬멧 없는 3/4 얼굴 — 앞·아래로 좁아지는 턱, 앞으로 치켜 올라간 눈 하나, 입. 머리카락은 행의 파트 |
| `hair` | 따라가기 | 머리의 위아래를 타고, 걸음의 bob보다 1/4박 늦게 뒤로 날린다. `at`을 머리 관절에 두고 점은 거기서부터 |
| `coat` | 따라가기 | 코트 원점(0,0)에 놓인 파트가 코트의 `rot` 흔들림을 그대로 받는다 — 잎 치마와 몸통이 따로 놀지 않는다 |
| `leg` / `leg_far` | 따라가기 | 다리 중심(`ctx["leg_mid"]`, `ctx["leg_rot"]`)에 놓인 파트가 엉덩이 둘레로 다리와 같이 돈다 |
| `leg_w` `leg_fill` `foot_fill` `organ_scale` `eye_fill` `mouth_fill` | 행 값 | 기본값은 예전 상수 그대로 |
| `smooth(ctrl)` | 도우미 | 제어점을 지나는 닫힌 곡선(Catmull-Rom). `(x, y, 1)`로 쓴 점만 모서리 — 잎 끝과 홈 |

색은 로스터에 맞췄다. 나머지 일곱은 무기 색을 `$steel` 쪽으로 반쯤 눅인 토큰
(`lichen` `ochre` `sage` `heather`)을 입는데, 첫 판의 미나는 진홍·산호 머리, 채도 높은
초록 가슴, 분홍 꽃, 금빛 눈이라 "혼자 너무 튄다"는 판정을 받았다. 그래서 머리는 같은
식으로 눅인 빨강 토큰 `madder`(#c46e77, 밑면·가르마는 `.dark`), 가슴과 치마는
`$sage.dark`·`$sage`, 눈은 `$ochre`, 입은 `$madder.dark`로 내리고, 꽃을 빼고, 갈기를
가로 85%·세로 92%로 줄였다(19파트). 필드 대비는 3.27 그대로다 — `madder`가 `$blood`보다
밝아서 채도를 내린 만큼 밝기가 받쳐 준다. 피부는 `$sage.light2`.

모양은 곡선으로 정리했다. 톱니처럼 갈라진 갈기와 지그재그 밑단이 둥근 일곱 옆에서
어수선하다는 판정("정갈하게")을 받아, 갈기·치마·가슴·앞머리를 모두 `smooth()`로
그리고 모서리는 잎 끝에만 남겼다. 갈기는 정수리에서 뒤로 넘어가 등 뒤로 떨어지는
