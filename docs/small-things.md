# 작은 물건 그리기 — 재료별 모듈, 견본 카드, 세 배율

> 소품 안의 작은 물건(자물쇠, 사슬, 시험관, 침구, 머그, 종이…)을 그릴 때의 순서다. 처음 적용한 곳은
> 기지(`ss.base.*`, `scripts/base.py`)다. 장면 전체의 구도와 빛은 feelers의 `docs/staging-method.md`가
> 맡고, 이 문서는 그 안에 놓이는 **물건 하나하나의 만듦새**를 맡는다.

## 0. 요약

1. 작은 물건은 문서 안에서 즉석으로 그리지 않는다. **재료별 모듈**(`scripts/bits_<재료>.py`)에 함수로
   한 번 그리고, 문서는 그 함수를 불러 놓기만 한다.
2. 물건은 **견본 카드**로 떼어 내서 본다. `npx tsx scripts/bits.ts <spec.py>`가 카드를 **세 배율**
   (1.2 / 2.4 / 8)로 나란히 그린다.
3. 8배에서는 **만들어졌는지**(부품이 제자리에 있는지), 2.4배와 1.2배에서는 **읽히는지**(무엇인지
   알아보는지, 잡음이 되지 않는지)를 본다. 셋 다 통과해야 끝난다.
4. 여럿이 나눠 그릴 때(서브에이전트)는 **파일 하나에 주인 하나**, 통합은 **한 사람**이 한다.

---

## 1. 왜 이렇게 하나

- **같은 물건이 여러 문서에 흩어져 있다.** 종이는 frame, shelf, bench, lab, board에, 유리병은 lamp,
  lander의 해치, lab의 창, Eden의 유품에 있다. 문서마다 즉석으로 그리면 품질이 제각각이고, 고칠 때도
  n번 고쳐야 한다. 함수로 한 번 그리면 한 번 고쳐서 모든 곳이 같이 좋아진다.
- **작은 물건은 큰 덩어리 안에서는 판단이 안 된다.** 6단위짜리 자물쇠는 캐비닛 문서 전체를 렌더한
  그림에서는 점 하나다. 떼어 내서 키워 봐야 고리가 몸통에 들어가는지 보이고, 실제 크기로 돌려 봐야
  그게 화면에서 자물쇠로 읽히는지 보인다.
- **디테일은 개수가 아니라 값의 구조다.** 게임 화면에서 작은 물건은 몇 픽셀이다. 거기서 잡음이 되는
  디테일은 없느니만 못하다. 그래서 크게 그리면서도 늘 실제 크기를 같이 본다.

## 2. 구조

| 파일 | 하는 일 |
| --- | --- |
| `scripts/draw.py` | 공통 도구. `P`, `R`, `shaded`(평평한 값 띠), `halo`, `band`, `bolt`, `lit_edge`, `ao`, `scratches`, `ring_arc`, 잉크 굵기 `INK_THIN`/`INK_HAIR`/`INK_FINE`, 그리고 `placed()` |
| `scripts/bits_<재료>.py` | 재료별 작은 물건. `metal`(자물쇠, 사슬, 걸쇠, 경첩…), `glass`(시험관, 거치대, 병, 주사기…), `cloth`(침낭, 침구, 자루, 밧줄…), `camp`(머그, 통조림, 종이, 계기판…), `keeps`(사물함 위 유품) |
| `scripts/base.py` | 기지의 문서들. 큰 덩어리를 그리고, 작은 물건은 bits를 불러 놓는다 |
| `scripts/specimen.py` | 견본 카드 `card(outdir, name, size, parts)`. `ss.bits.*` id의 일회용 문서를 스크래치 폴더에 쓴다 |
| `scripts/bits.ts` | spec 스크립트를 돌려 카드를 받고, 배율마다 나란히 그려 PNG 한 장으로 만든다 |

함수의 모양은 하나로 맞춘다.

```python
def padlock(prefix, x, y, s=1.0, rot=0.0, **options):
    """무엇인지 한 줄, 옵션이 무엇을 바꾸는지 한 줄. 원점은 몸통 중심."""
    parts = [ ...원점 둘레에, 캠프에서의 실제 크기로... ]
    return placed(parts, (x, y), s, rot)
```

- **원점에 자연 크기로 그린다.** 원점이 중심인지 발인지 docstring에 적는다. 놓는 곳, 크기, 회전은
  `placed()`가 한 덩어리로 처리한다(각 파트의 `at`을 돌리고, `rot`을 더하고, `scale`을 곱한다).
- **id는 모두 `prefix`에서 만든다**(`f"{prefix}_body"`). 한 문서에 같은 물건이 여럿 있어도 겹치지 않는다.
- **애니메이션이 잡을 파트는 이름을 고정한다.** 계기판 바늘은 `{prefix}_needle`이고 `at`이 회전
  중심이다. 램프의 caps는 `cap()`이 만드는 `{prefix}_lit`이다. 문서의 트랙이 이 id를 부른다.
- **옵션은 캠프에 실제로 필요한 변형만 둔다.** 색, 수위, 열림/닫힘, 길이, 손잡이 방향 정도다. 모든 것을
  옵션으로 열지 않는다.

## 3. 세 배율

| 배율 | 무엇을 흉내 내나 | 보는 것 |
| --- | --- | --- |
| **1.2** | 일반 데스크톱. feelers의 `WORLD_ZOOM` 1.2 × DPR 1 | 잡음이 되지 않는가. 안 읽히면 단순화하거나 키운다 |
| **2.4** | 고해상도 화면. `WORLD_ZOOM` 1.2 × DPR 2. 기지 텍스처는 2배로 구워 절반으로 그린다 | 실루엣과 두세 개의 값만으로 무엇인지 알아보는가 |
| **8** | 그림 자체 | 부품이 제자리에 있는가 |

8배에서 묻는 것은 이런 것이다.

- 자물쇠의 고리 두 다리가 몸통 **안으로** 들어가는가. 열쇠 구멍이 있는가.
- 사슬 고리가 **맞물리는가**. 정면 고리(구멍이 보이는 타원)와 옆면 고리(굵은 막대)가 번갈아 오는가.
- 시험관 바닥이 **둥근가**. 액체에 메니스커스와 자기 그늘이 있는가. 유리 입구에 테가 있는가.
- 말아 둔 침낭 끝에 **말린 나선**이 보이는가. 끈에 버클과 남는 끈 꼬리가 있는가.
- 종이에 접힌 모서리가 있고, 쓴 것이 **짧은 선**으로 되어 있는가(글자는 쓰지 않는다).

2.4배와 1.2배에서 안 읽히는 물건이 있으면, 디테일을 더하지 말고 **값을 정리하거나 크기를 키운다.**
키울 크기는 숫자로 적어 통합하는 쪽에 넘긴다.

## 4. 그리는 원칙

공통.

- **빛은 왼쪽 위에서 온다.** 덩어리마다 밝은 가장자리 하나, 반대쪽은 그늘, 닿는 곳에는 어두운 선
  (`lit_edge`, `ao`).
- **평평한 값만 쓴다.** Phaser 어댑터는 그라디언트를 가운데 색 하나로 그린다. 값이 바뀌는 곳은 따로
  자른 띠(`shaded`)로 그린다.
- **잉크 굵기**는 큰 덩어리에 `INK_THIN`(2), 소품에 `INK_HAIR`(1), 10단위 미만의 물건에 `INK_FINE`
  (0.6)을 쓴다. 안쪽 디테일에는 보통 외곽선을 넣지 않는다.
- **색은 소유를 따른다.** 원정대가 가져온 것은 차갑다(steel, slate, frost). 종이는 bone/husk, 젤리는
  gold이고, 빛은 버섯의 teal뿐이며 그것도 빌린 것이다. 분홍은 하이브의 신호라서 아낀다. 세상에 글자는
  없다.
- **결정적으로 그린다.** `random`은 쓰지 않는다. 흩뿌릴 일이 있으면 `scratches()`처럼 고정된 LCG를 쓴다.

재료별.

| 재료 | 읽히게 하는 것 |
| --- | --- |
| 금속 | 두 값(밝은 면, 그늘 면)과 가는 하이라이트 하나. 이음매(경첩 핀, 리벳, 나사)는 한쪽에 모은다. 녹은 이음매에서 아래로 흐른다 |
| 유리 | 옅은 frost 틴트 위로 내용물 색이 비친다. 왼쪽에 강하고 좁은 세로 하이라이트, 오른쪽에 가는 것 하나, 입구에 테가 있다. 내용물은 **뒤 유리와 앞 반사 사이**에 놓는다 |
| 천 | 차가운 색에 끈과 바늘땀은 bone이다. 접힘은 **긴장점**(묶인 곳, 눌린 곳, 매달린 곳)에서 퍼진다. 솔기와 무게가 내려앉은 바닥이 천을 천으로 보이게 한다 |
| 종이 | 접힌 모서리, 오른쪽이 들쭉날쭉한 짧은 선, 압정이나 테이프, 돌 문진을 쓴다. 겹친 종이는 가장자리를 조금씩 어긋나게 둔다 |

## 5. 견본 카드와 미리보기

spec 스크립트는 `python3 <spec.py> <dir>`로 실행되고, `card()`를 여러 번 불러 카드를 쓴다.

```python
import sys
sys.path.insert(0, "/home/user/PolyGraphics/scripts")
from draw import *
from specimen import card
from bits_metal import padlock, chain

out = sys.argv[1]
card(out, "padlock", (16, 16), padlock("lock", 0, 2))
card(out, "cellar_door", (48, 56), [...문 판...] + chain("ch", [(-18, -14), (16, 14)]) + padlock("lock", 6, 9))
```

```
npx tsx scripts/bits.ts path/to/spec.py                  # → out/bits/spec.png (1.2 / 2.4 / 8)
npx tsx scripts/bits.ts spec.py --scales 2.4,8 --out /tmp/x.png
npx tsx scripts/bits.ts --json some/dir                  # 이미 써 둔 카드(또는 복사해 온 문서)를 그린다
```

- 카드 하나에 **변형 몇 개**(열림/닫힘, 수위, 색)를 같이 놓는다.
- **실제 크기 장면 카드**를 꼭 하나 둔다. 사슬이 감긴 캐비닛 문, 탁자 가장자리의 거치대와 주사기,
  사물함 뚜껑 위의 유품처럼, 물건은 맥락 안에서 판단한다.
- **지금 모습과 비교한다.** `apps/ss/assets/ss-base-*.json`을 `--json` 폴더에 복사해 같이 그리면 무엇을
  고치는 중인지 보인다.
- 카드는 `use`로 실제 문서를 부를 수 있다(예: `ss.pickup.food`). ss 앱의 토큰과 문서로 그리기 때문이다.
- spec 스크립트와 카드는 스크래치 폴더에 둔다. 라이브러리에는 들어가지 않는다.

## 6. 나눠 그리기 (서브에이전트)

물건이 많을 때는 재료 묶음마다 한 명씩 나눠 맡긴다. 기지에서는 다섯 명이 동시에 그렸다
(metal, glass, cloth, camp, keeps).

- **파일 하나에 주인 하나.** 각자 자기 `bits_<재료>.py`와 자기 스크래치 폴더에만 쓴다. `base.py`,
  `draw.py`, `rig.py`, 토큰, 에셋 JSON은 건드리지 않는다. 같은 파일을 여럿이 고치면 나중에 쓴 쪽이
  먼저 쓴 쪽을 덮는다.
- **공유 출력을 다시 쓰는 명령은 금지한다.** `npm run check`, `render`, `dist`는 `out/`과 `dist/`를 다시
  쓴다. 미리보기는 `scripts/bits.ts`로만 한다(`--out`을 자기 스크래치로 준다). 커밋도 하지 않는다.
- **공통 브리프 하나와 묶음별 과제**를 준다(§9). 묶음별 과제에는 물건 목록, 각 물건이 지금 캠프 어디에
  있는지(문서와 파트 id), 요구하는 장면 카드가 들어간다.
- **돌려받을 것을 정해 둔다.** 함수 시그니처, 원점, 자연 크기(s=1에서의 범위), 옵션, 애니메이션이 쓸
  id, 대체할 위치(문서와 파트 id), 크기 권고, 최종 시트 경로다. 짧게 받는다. 읽는 사람은 통합하는
  사람이다.
- **통합은 한 사람이 한다.** 물건 하나가 여러 문서에 쓰이고, 문서 하나에 여러 재료가 섞이기 때문이다.

## 7. 통합 체크리스트

- [ ] `base.py`의 즉석 파트를 bits 호출로 바꾼다. 놓는 위치와 크기는 원래 자리에 맞춘다.
- [ ] 애니메이션 트랙이 부르는 id가 그대로 있는지 본다(`npm run check`가 없는 id를 잡는다).
- [ ] **문서 크기를 바꾸지 않는다.** feelers가 발 위치와 충돌을 문서 크기에 맞춰 두었다(`src/data/hub.ts`의
      `BASE_FOOT`, 각 prop의 `block`). 바꿔야 하면 그쪽도 같이 고친다.
- [ ] `python3 scripts/base.py && npm run check`
- [ ] 기지 문서를 `scripts/bits.ts --json`으로 다시 그려 전후를 비교한다.
- [ ] feelers에서 PolyGraphics 커밋으로 핀을 올리고, DPR 2 스크린샷으로 실제 화면에서 확인한다.

## 8. 적용 기록

### 2026-10-05 — 기지의 작은 물건

- 공통 도구를 `scripts/draw.py`로 분리했다(출력은 그대로). `INK_FINE`과 `placed()`를 더했다.
- 서브에이전트 다섯이 동시에 그렸다. 묶음마다 20~30분이 걸렸고, 통합은 한 사람이 묶음이 끝나는 대로 했다.

| 모듈 | 물건 | 들어간 곳 |
| --- | --- | --- |
| `bits_glass` | 시험관, 거치대, 시료병, 주사기, 병, 카트리지 | 작업대(한 칸 빈 거치대와 그 한 칸이 든 주사기), 시료저장고, 등 다섯 곳 |
| `bits_camp` | 머그, 통조림, 종이, 종이 더미, 꼬리표, 계기판, 의자, 국자, 톱, 돌 | 텐트, 물탱크, 서가, 빨랫줄, 젤리 통, 작업대, 화로, 지도판, 식량창고, 시료저장고, 연구소, 톱 |
| `bits_cloth` | 침낭, 펼친 침구, 베개, 자루, 밧줄 타래, 문 천 | 텐트, 식량창고, 연구소, 침낭 |
| `bits_metal` | 자물쇠, 사슬, 걸쇠, 경첩, 죔쇠, 고리, 전선 뭉치 | 시료저장고, 사물함, 착륙선 해치, 젤리 통, 물탱크, 등, 연구소 |
| `bits_keeps` | 사물함 위 유품 여덟 | `ss.base.keep-*` |

배운 것.

- **`rot` 트랙의 키는 오프셋이다.** 렌더러와 어댑터 모두 파트 자신의 `rot`에 트랙 값을 **더한다**. 기존
  문서의 트랙 다섯 개(계기판 바늘, 꼬리표, 텐트와 서가의 종이, 빨랫줄의 종이)가 절대 각도로 적혀 있어서
  두 배로 돌고 있었다. 이제 모두 `(0, 0)`에서 시작한다.
- **흔들리는 물건은 한 점에 모은다.** 파트마다 `at`이 다르면 같은 회전 트랙을 줘도 제각각 돌아서 물건이
  흩어진다. `pivoted()`(bits_camp)로 모든 파트의 `at`을 축(압정, 매듭, 고리)에 모으고 모양을 그만큼 옮겨
  두면, 트랙 하나로 물건 전체가 그 점을 중심으로 돈다. 종이, 꼬리표, 자물쇠, 자루 끈이 이렇게 되어 있다.
- **유리는 층으로 그린다.** 뒤 유리 → 내용물 → 앞 반사 → 잉크 테두리 → 입구/마개 순서다. 그래서
  `jar(contents=…, behind=…)`처럼 내용물을 **끼워 넣는** 형태가 되었고, 램프의 caps와 빛 무리도 그 안에
  들어간다. id는 호출하는 쪽이 정하므로 애니메이션 트랙이 그대로 산다.
- **놓이는 물건은 발을 원점으로 둔다.** 유품은 문서의 y=+7에 발이 있다(`bits_keeps.FOOT`). feelers는
  유품을 가운데가 아니라 발로 세워 사물함 뚜껑에 올린다(`KEEP_FOOT`, `LOCKER_LID`).
- **이야기가 되는 디테일이 가장 잘 읽힌다.** 거치대의 빈 한 칸과 그 시료가 든 주사기, 사슬이 손잡이를
  지나 자물쇠로 모이는 길, 뒤집어 접힌 침낭 위의 눌린 자국 같은 것들이다. 개수를 늘린 디테일보다 1.2배에서
  먼저 읽힌다.
- **게임이 말할 것은 그림에 그리지 않는다.** 사물함은 걸쇠만 있고 자물쇠는 없다. 어느 사물함이 열려
  있는지는 게임이 알파 값으로 말한다. 하나의 텍스처에 자물쇠를 그려 두면 잠기지 않은 사물함도 잠겨 보인다.
- **에이전트끼리 같은 문서를 건드린다.** 각자 장면 카드를 만들 때 캠프 문서를 읽어 오는데, 그 사이 다른
  묶음이 통합되며 좌표가 바뀌었다(예: 물탱크 컵, 등의 병). 장면 카드는 매번 JSON을 새로 읽게 하고,
  돌려받는 좌표는 "끝났을 때의 문서 기준"으로 받는다.
- **부품 수는 늘어도 된다.** feelers는 기지 텍스처를 부팅 때 한 번 굽는다(움직이는 문서는 프레임마다
  굽는다). 텐트의 천 파트가 약 11개에서 약 133개로 늘어도 굽는 시간이 조금 늘 뿐, 구운 뒤 화면에 그리는
  비용은 같다. 움직이는 문서는 프레임 수만큼 곱해진다는 것만 기억한다.
